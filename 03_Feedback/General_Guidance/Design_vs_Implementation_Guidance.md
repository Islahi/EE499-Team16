# Classroom Guidance — Engineering Design vs Implementation

**Source:** `WhatsApp Image 2026-09-20 at 12.28.32.jpeg`  
**Nature:** classroom/presentation guidance preserved as supporting feedback; not treated as a replacement for the official EE499 guideline document.

The photographed slide is titled **“What This Means for ECE Projects.”** Its key distinction is:

| Project type | Engineering design | Implementation |
|---|---|---|
| Software | Architecture, algorithms, interfaces, data flow, control logic | Coding, debugging, testing, integration |
| Simulation | Mathematical model, assumptions, parameters, numerical method, validation plan | Running simulations, collecting outputs, checking behavior |
| Hardware | System architecture, topology, component selection, calculations, safety/performance analysis | Building, assembling, soldering/fabricating, testing prototype |

The slide also notes that most projects contain more than one type of design.

## Relevance to Team 16

The project is strongly simulation/software-oriented. Therefore, simply producing code or simulation outputs is not enough if the mathematical model, assumptions, parameters, interfaces, numerical method, and validation plan are still under-defined. Term 2 implementation should proceed together with repair of any design definition needed to make the implementation credible and testable.
